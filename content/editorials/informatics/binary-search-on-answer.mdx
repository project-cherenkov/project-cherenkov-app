## The problem

A game host chooses a whole number from 1 to 1,000,000. You may ask
only yes-or-no questions. Can you always identify the number in at most
20 questions? There are $2^{20}=1,048,576$ possible sequences of answers,
so the number of possible outcomes is large enough. But what questions
would narrow the possibilities reliably?

Now consider a less familiar version: find the smallest speed that
allows a car to finish a race within a time limit. There is no sorted
array to search. What structure would make a halving strategy possible?

## The idea

Binary search needs a *predicate*: a yes-or-no question $P(i)$ about
each candidate index $i$. For $n$ candidates, the indexes run from 0
through $n-1$. The predicate must be *monotonic*, which
means that, as the index increases, its answers change at most once
from false to true. The sequence might look like
$F,F,F,F,T,T,T,T$. Binary search locates the boundary between the two
regions.

Sorted arrays create a familiar example. For the first index where
$a_i \ge \text{target}$, define $P(i)$ to be true exactly when
$a_i \ge \text{target}$. Sortedness guarantees that once the condition
becomes true, it stays true. But an array is not required. If a car can
finish a race in time at one speed, every higher speed can do so too,
provided the other conditions stay fixed. The same false-to-true
pattern appears when testing candidate speeds or budgets.

The displayed values use $0$ for false and $1$ for true. Step through
the lower-bound search and watch the interval close around the first
true position. The interval is half-open: its left boundary is included
and its right boundary is excluded.

## Full proof

**Claim.** If $P$ is monotonic over the indexes $0$ through $n-1$, the
half-open lower-bound search returns the first index where $P$ is true,
or returns $n$ if $P$ is never true.

**Invariant.** At the start of every iteration, every index before $lo$
is false, every index from $hi$ onward is true, and the boundary $b$
(the first true index, or $n$ if none exists) lies in the closed range
$[lo, hi]$. The search window itself is half-open, $[lo, hi)$.

**Base case.** Initially $lo=0$ and $hi=n$. No index is before $lo$ or
at or beyond $hi$, and the boundary $b$ must lie between 0 and $n$.
So the invariant holds.

**Inductive step.** While $lo < hi$, choose
$mid=lo+\lfloor(hi-lo)/2\rfloor$. This index is inside the half-open
window.

- If $P(mid)$ is true, monotonicity means every index at or after
  $mid$ is true. The first true boundary is therefore no greater than
  $mid$. Set $hi=mid$, keeping $mid$ as a possible boundary.
- If $P(mid)$ is false, every index at or before $mid$ is false. The
  first true boundary must be greater than $mid$, or equal to $n$ if
  no true index exists. Set $lo=mid+1$.

Both updates preserve the invariant. The true case keeps $mid$ as a
possible answer, while the false case removes it.

**Termination.** Each iteration reduces the width $hi-lo$ to at most half its previous
value, rounded down, so the loop takes $O(\log n)$ steps. When $lo=hi$, the
search window is empty and the invariant forces $b=lo$. Returning $lo$
therefore gives the first true index, or $n$ when no index is true.
$\blacksquare$

**Where it breaks in practice.** If a predicate changes from false to
true and then back to false, there is no single boundary for binary
search to locate. The fact that candidate values are numerically
ordered does not make a predicate over them monotonic. Check the truth
pattern before using this search.
